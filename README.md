# Karwa0 — Phase 6: Real Trip Lifecycle

المرحلة السادسة تحول النموذج إلى دورة رحلة مترابطة فوق Phase 5.

## ما تمت إضافته
- قبول الطلب بمعاملة Firestore Transaction لمنع قبول الطلب نفسه من أكثر من كابتن.
- دورة حالات: بانتظار كابتن → الكابتن في الطريق → وصل الكابتن → بدأت الرحلة → تم الوصول.
- تسجيل أوقات القبول والوصول والبدء والإكمال داخل الطلب.
- رمز بدء رحلة OTP يظهر للعميل ويُطلب من الكابتن قبل بدء الرحلة.
- استمرار مشاركة موقع الكابتن المباشر أثناء الرحلة ورسم موقعه للعميل.
- إلغاء العميل مع سبب اختياري، مع إظهاره للإدارة.
- حالة دفع: المحفظة مدفوعة فور الحجز، والنقد يتحول إلى مدفوع عند إكمال الرحلة.
- تثبيت العمولة وصافي ربح الكابتن مع الطلب.
- لوحة الإدارة تعرض الرحلات المباشرة، الملغاة، الكباتن المتصلين، والإيرادات.
- قواعد Firestore محدثة لدورة الحالات الجديدة وصلاحيات العميل/الكابتن/الإدارة.

## التشغيل
انشر `firestore.rules` في Firebase ثم شغّل الملفات عبر خادم محلي/استضافة HTTPS (وليس file://) حتى تعمل ES Modules وGeolocation بشكل صحيح.

## ملاحظة إنتاجية مهمة
رمز OTP في هذه النسخة يعمل وظيفيًا داخل تطبيق الويب، لكنه ليس حاجزًا أمنيًا إنتاجيًا لأن التحقق يتم في العميل. قبل الإطلاق الحقيقي يجب نقل إنشاء/التحقق من OTP وتثبيت السعر النهائي والتسوية المالية إلى Backend موثوق (Cloud Functions أو API خاص)، وعدم إتاحة سر OTP للكابتن عبر مستندات قابلة للقراءة.

## المرحلة التالية المقترحة
Phase 7: مصادقة الهاتف OTP حقيقية، Backend/Cloud Functions، إشعارات Push، مستندات الكابتن، محفظة وتسويات مالية، وسجل تدقيق للأحداث.
